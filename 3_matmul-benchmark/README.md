# Пункт 3. Умножение X16 на сжатые веса Llama-3.2-1B-Instruct

В пункте 1 мы сжали веса. Теперь проверяем, сколько времени занимает умножение `X @ W.T` с этими весами. Берём пять размеров матриц из Llama и для каждого подаём на вход 128, 512 и 2048 токенов. Получаем 15 замеров для каждого способа умножения.

Сравниваем исходные 16-битные веса и два варианта INT4. В обоих вариантах INT4 один байт хранит два веса, а на каждую строку приходится один масштаб FP32. В режиме `absmax` масштаб задаёт самый большой по модулю вес строки. В режиме `mse` пробуем 18 масштабов и выбираем тот, с которым ошибка восстановления весов меньше. Дальше оба набора весов попадают в один и тот же кернель умножения.

## Запуск в Colab

Выберите в Colab среду с GPU, загрузите ноутбук и выполните все ячейки. Код кернелей уже внутри. На T4 и других картах Turing ноутбук берёт FP16, на поддерживаемых картах Ampere и новее — BF16. ## Как мы измеряли время

- **Входные данные.** Берём размеры слоёв Llama и заполняем матрицы случайными числами. Для каждой формы запускаем NumPy PCG64 с `SeedSequence([42, индекс формы])`, создаём веса порциями по 1024 строки, затем генерируем активации для трёх длин. Так мы воспроизвели входные данные архивного замера.
- **Проверка расчёта.** Каждую из пяти матриц квантизуем обоими способами на GPU. Для 16 строк каждой матрицы отдельно перебираем масштабы на CPU и сверяем упакованные байты и масштабы. На всех 80 проверенных строках MSE выбрал масштаб меньше исходного. Затем для каждого метода и размера проверяем 256 элементов произведения. Эталон считаем в FP64, суммируя по всем `K` элементам. Допуски — `rtol=0.005` и `atol=0.01`.
- **Повторы.** Сначала прогреваем каждый из трёх методов четыре раза. Затем меняем порядок вызовов, перебирая все шесть перестановок. Обычно делаем 12 замеров на метод, для самого большого случая (`lm_head`, 2048 токенов) — 6. В архивном тесте было 8 и 4 повтора соответственно. Компилируем кернели, переносим данные, квантизуем веса и проверяем расчёт до начала замеров. CUDA-событиями измеряем только умножение, под результат заранее выделяем память.
- **Видеокарта и библиотеки.** NVIDIA GTX 1660 Ti (SM75), драйвер 610.47, Triton 3.8.0, NumPy 2.4.2. Активации и результат храним в FP16, сумму накапливаем в FP32. Для cuBLASLt 12.4.5.8 (120405) задали редукцию в FP32 и лимит рабочей памяти 32 МиБ.

В CSV и JSON сохранён прогон, из которого взяты числа таблицы. Поле `quantizer_sha256` в этом JSON содержит хеш отдельного файла с MSE-квантизатором. С тех пор оба квантизатора объединили в модуле пункта 1, поэтому при повторном запуске хеш будет другим. Код кернеля умножения для SM75 совпадает побайтово с версией из замера.

## Как повторить замер на Windows

Для скрипта нужны видеокарта SM75, NumPy, совместимая версия Triton для Windows и PyTorch. PyTorch нужен для импорта кернелей, сами вычисления скрипт запускает через CUDA Driver API. В PowerShell из корня проекта укажите путь к папке с `cublasLt64_12.dll` из NVIDIA cuBLAS 12.4.5.8 и библиотеками CUDA Runtime 12.4.127. Для результатов выберите новую папку.

```powershell
$env:TASK3_CUBLAS_DIR = 'D:\path\to\cuda-dlls'
py -3.13 -B -X utf8 3_matmul-benchmark/microbench/run.py --output my_task3_results
```
