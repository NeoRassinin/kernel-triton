# Пункт 2: BF16 × INT4 на Triton

`bf16_int4_matmul.py` реализует инференс `Y = X @ W_dequant.T` без полной
деквантизации весов в глобальную память. Квантование из пункта 1, бенчмарки
из пункта 3 и интеграция модели из пунктов 4–5 остаются отдельными задачами.

Подробный учебный разбор каждого шага: [Markdown](docs/bf16_int4_walkthrough.md)
и [PDF с рисунками и полным исходным кодом](docs/bf16_int4_walkthrough.pdf).

## Согласованный формат

- `x`: BF16 `[M, K]`, где `M` — число входных векторов/токенов.
- `packed`: INT8 `[N, K // 2]`. Размерность `K` должна быть чётной.
- Упаковка вдоль `K`: `q[n, 2*j]` в младших 4 битах,
  `q[n, 2*j+1]` в старших.
- Signed INT4 в дополнительном коде; квантователь использует `[-7, 7]`.
- `scales`: FP32 `[N]`; `W_dequant[n, k] = q[n, k] * scales[n]`.
- Для нулевой строки `q = 0`, `scale = 1`. Zero-point и группы отсутствуют.
- Выход: BF16 `[M, N]` по умолчанию, опционально FP32.
- Все тензоры должны находиться на одном CUDA-устройстве. Поддерживаются
  как непрерывные тензоры, так и представления с произвольными шагами
  (strided views); выход всегда contiguous.

Выходы обоих вариантов квантователя (`two_pass` и `fused`) из
`triton_int4_task1.ipynb` совместимы с этим интерфейсом. Интеграционные тесты
запускают реальные кернели из ноутбука, затем передают их выходы в matmul.
Менять формат или GPU-кернель умножения для этого не требуется.

Квантователь в ноутбуке использует пороговую арифметику с округлением
половин от нуля: например, `0.5 → 1`, `-0.5 → -1` при scale=1.
Это отличается от `torch.round`, округляющего половины к ближайшему
чётному. Matmul принимает готовые INT4 и не зависит от этого выбора;
в точном тесте квантователя нельзя подменять его арифметику `torch.round`.

## Использование

```python
import torch
from bf16_int4_matmul import matmul_bf16_int4

# packed, scales получены от квантователя коллеги для W[N, K].
# x — BF16 CUDA-тензор [M, K].
with torch.inference_mode():
    y = matmul_bf16_int4(x, packed, scales)
    y_fp32 = matmul_bf16_int4(x, packed, scales, out_dtype=torch.float32)
```

Чтобы соединить оба пункта прямо в ноутбуке коллеги, выполните ячейки
с импортами и определениями кернелей/функций (ячейки 1, 3, 5, 7 при
отсчёте с нуля), затем добавьте следующую ячейку. Файл
`bf16_int4_matmul.py` должен лежать в текущей папке ноутбука или быть
доступен через `PYTHONPATH`.

```python
from bf16_int4_matmul import matmul_bf16_int4

W = torch.randn(512, 2048, device="cuda", dtype=torch.float16)
X = torch.randn(128, 2048, device="cuda", dtype=torch.bfloat16)

with torch.inference_mode():
    packed, scales = quantize_fp16_to_int4_packed(W, method="two_pass")
    Y = matmul_bf16_int4(X, packed, scales)  # BF16 [128, 512]
```

Для пункта 3 подготовьте `packed, scales` до начала измерения matmul.
Сравнение `X @ W_bf16.T` и `matmul_bf16_int4(X, packed, scales)` должно
выполняться на одном GPU. Квантование FP16-весов на T4 поддерживается,
но этот BF16 matmul требует GPU с нативным BF16 (например, RTX 5060,
A100, L4). Проверка `torch.cuda.is_bf16_supported(including_emulation=False)`
отличает нативную поддержку от возможной эмуляции средствами PyTorch.

Вход `[batch, tokens, K]` перед вызовом нужно преобразовать в `[M, K]`, где
`M = batch * tokens`, затем восстановить ведущие размерности результата.
Bias не включён. Autograd/backward не реализован.

## Как считается результат

Один экземпляр программы вычисляет блок результата. На каждом шаге по `K`
он загружает блок `X` и упакованный блок весов. Каждый байт читается один раз
в логическом блоке, распаковывается в два signed INT4 и преобразуется в BF16.
Все целые числа диапазона INT4 представимы в BF16 точно.

Поскольку масштаб постоянен для всей строки весов, его можно вынести из суммы:

```text
Y[m, n] = sum_k(X[m, k] * q[n, k]) * scales[n]
```

Умножение блоков выполняет `tl.dot` с FP32-аккумулятором. FP32-scale
применяется после завершения редукции, перед приведением выхода к BF16.
Это экономит операции и избегает округления каждого `q * scale` к BF16.
Полный временный тензор восстановленных весов не создаётся.

При сравнении с PyTorch основной эталон:

```python
# q — независимо распакованные целые веса [N, K].
# Для точного FP32-эталона отключите TF32 при необходимости.
reference = (x.float() @ q.float().T) * scales[None, :]
```

Также подходит `x.float() @ (q.float() * scales[:, None]).T` с допуском
на FP32-округления. Вариант `x @ (q.float() * scales[:, None]).bfloat16().T`
дополнительно округляет веса к BF16 и может отличаться сильнее. Сравнение
с исходной неквантованной `W` включает ошибку квантования и не является
изолированной проверкой корректности matmul-кернеля.

Хвосты блоков по `M`, `N`, `K` защищены масками. Нечётный `K` отклоняется,
поскольку согласованный формат не предусматривает дополнительный полубайт.

## Окружение и проверка

Для BF16-умножения на NVIDIA нужна Ampere или более новая архитектура.
RTX 5060 подходит. T4, на которой проверялся квантователь коллеги, не имеет
нативного BF16-умножения: для этого кернеля используйте совместимый GPU.
Работоспособность FP16-квантователя на T4 не означает поддержку BF16 matmul.

Проверено на RTX 5060: Python 3.13.7, PyTorch 2.11.0+cu128,
triton-windows 3.7.1.post27. Исходные 37 тестов проверяют сам matmul.
Дополнительно добавлены 22 интеграционных случая для реальных
квантователей из ноутбука: оба метода, FP16/BF16-веса, нулевые строки,
хвосты, границы округления и размеры проекций модели.
Общий результат проверки: **59 passed**, без пропущенных GPU-тестов.

```powershell
python -m pytest -q
```

Только проверка цепочки «ноутбук пункта 1 → matmul пункта 2»:

```powershell
python -m pytest -q tests/test_task1_integration.py
```

Тесты извлекают только шесть определений из ноутбука во временный `.py`,
чтобы Triton видел исходник JIT-функций. Ячейки бенчмарков, вывода примеров
и записи JSON из ноутбука при этом не выполняются. Исходный ноутбук не меняется.

Тесты проверяют известные байты, знаки и порядок полубайтов, все значения
`[-7, 7]`, нулевые строки, FP16-квантование по согласованной формуле,
хвосты блоков, strided views, нестандартный CUDA-stream, пустые размерности
и неправильные входы. Отдельно проверяются размеры проекций
`[2048, 2048]`, `[512, 2048]`, `[8192, 2048]`, `[2048, 8192]`
при `M = 128, 512, 2048`. Это проверки корректности, а не бенчмарк скорости.

CUDA-тесты пропускаются, если совместимый GPU недоступен. Нужны PyTorch
с CUDA, Triton (на Windows — совместимый `triton-windows`) и pytest.
Для NVIDIA требуется GPU с нативной поддержкой BF16, Ampere или новее.
RTX 5060 подходит. На T4 нет нативного BF16: для него нужен отдельный
FP16-вариант и отдельное согласование условий сравнения.

Для воспроизводимого бенчмарка следует прогреть кернель, исключить JIT и
квантование из времени matmul и измерять GPU-время с синхронизацией.
Ускорение относительно BF16 зависит от GPU и размеров матриц; текущие
размеры блоков — начальная конфигурация, без autotune и обещаний ускорения.
